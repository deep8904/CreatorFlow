# Known Issues / Deferred Items

Items intentionally not fixed in this pass, with severity and reasoning. Per the bounded fix-and-reverify loop in the implementation plan (max 3 QA↔fix rounds), anything still open after round 3 lands here rather than being looped on indefinitely.

| Item | Severity | Reasoning |
|---|---|---|
| `.label-eyebrow` tick-mark decoration not extended in-app | P2 | The underlying mono-uppercase label *system* is already shared between marketing and in-app; only the decorative `::before` tick-mark line is marketing-exclusive. Cosmetic, not structural — see `docs/DESIGN_SYSTEM.md` finding #20. |
| Real Google OAuth for Gmail/YouTube | Out of scope | Requires provisioning real Google Cloud OAuth credentials, which this session doesn't have access to. CLAUDE.md treats this as a distinct, security-sensitive infra project (encrypted token storage, explicit refresh logic). Settings already handles the gap honestly (disabled "Connect" + tooltip). |
| Live AI features (contract review, reply drafting, video-transcript analysis, Gmail classification) | Out of scope | Explicit P1/P2 in `docs/PRD.md`. Static/demo versions get honestly labeled as previews rather than left implying they're live (Phase 3), but no LLM integration is built here. |
| Gmail classifier (`lib/integrations/gmailClassifier.ts`) has zero callers | P2 | Dead code — a distinct backend-integration project (polling/webhook infra) beyond this UI/UX + flow-correctness pass. |
| Automations have no backend trigger/listener | Known, already honest | `AutomationsBoard.tsx` already labels this "coming in a future update." Toggling only flips a DB boolean today — correct and disclosed, not a bug. |
| In-app board layouts (Deals' 3-column kanban, Drafts' fixed-width list+editor split, similar patterns elsewhere) don't reflow below ~768px | P2 | These are fixed-width multi-panel `flex` layouts designed for desktop use (the product's primary context, per `docs/PRD.md` — a deal/content management tool, not a mobile-first app). Below tablet width they become visually cramped (small tap targets, tight text) but nothing is destructively clipped or unreachable — all content stays in the DOM and scrollable. The app shell's own navigation (the more severe issue — the sidebar previously ate 60%+ of a 375px viewport with no way to collapse it) was fixed with a proper mobile drawer/hamburger pattern (see `docs/qa/QA_REPORT.md` QA-APP-001). A full per-board mobile redesign (stacked panels, horizontal-scroll kanban, etc.) is a substantial project in its own right — sized more like a new phase than a QA-round fix — and is deferred here rather than attempted piecemeal. |
| Disconnecting Gmail/YouTube on the seeded demo account is irreversible through the UI | Operational caution, not a bug | Since real OAuth isn't wired (see above), Settings' "Connect" affordance is an honest disabled state, not a working reconnect flow. Clicking "Disconnect" on the demo account during a live walkthrough removes the seeded `integrations` rows with no in-app way back — recovering requires a direct database insert. Documented so it isn't repeated: avoid clicking "Disconnect" on the demo account outside of intentional testing. |
| Drafts have no lifecycle/status field (DRAFT-003) | P2 | Ideas at least has a status field (now editable, see Round 3 fixes); Drafts is a flat list sorted only by `updated_at`. Adding a lifecycle (draft/in-review/ready/published) is a real feature, not a QA-round patch — deferred from the Round 3 audit's fix pass. |
| No full-text search over draft content (DRAFT-004) | P2 | Round 3 added title-substring search to Ideas and Deals; Drafts' bodies are exactly the content that would benefit most from real search, but that's a bigger feature (search index or server-side query) than the client-side substring filter used for the other two. Deferred from the Round 3 fix pass. |
| No search on Automations or Team (XCUT-001, partial) | P2 | Round 3's search fix covered Ideas and Deals only, the two modules the audit specifically named as list-shaped and growing. Automations is a small fixed preset list; Team is capped at owner + one collaborator on the free plan — neither currently needs search. Revisit if either constraint changes. |
| No avatar upload (SET-003) | P2 | `profiles.avatar_url` exists in the schema but nothing sets it; every avatar is a generated initials chip. Needs a Supabase Storage bucket + upload UI — a real feature, not a Round 3 fix-pass item. |
| `profiles.timezone`/`profiles.locale` are unused schema columns (SET-004) | P2 | Defined in `lib/supabase/types.ts`, never read or written. All dates currently format via the browser's local `Intl` default. Either wire these up (requires deciding what should respect them — analytics dates? due dates?) or drop the columns; deferred rather than guessed at during the Round 3 fix pass. |
| No notification system (XCUT-002) | P2 | No bell icon, notification center, or sidebar badges. "Needs your attention" only surfaces on Dashboard. A real feature (needs a data model for what counts as a notification, read/unread state, etc.), out of scope for a QA fix pass. |
| No bulk actions anywhere (XCUT-003) | P2 | No multi-select on Ideas, Deals, or Drafts. Now that single-record delete exists for all three (Round 3), this becomes more relevant once someone has a real backlog to clean up — revisit then rather than build ahead of need. |
| No membership audit trail (TEAM-004) | P2 | No record of who invited/removed whom or when. Low severity while the free plan caps teams at owner + one collaborator; revisit if team size grows. |
| Pre-existing helper functions (`is_account_member`, `is_account_owner`, `handle_new_team_owner`, `handle_new_user`) are flagged as anon-executable by Supabase's security advisor | P2 | All four are `SECURITY DEFINER` and internally scoped to `auth.uid()`, so an anonymous caller gets nothing back — not exploitable in practice. Round 5 fixed this same class of finding for `accept_team_invite`/`transfer_account_ownership` (see `docs/qa/QA_REPORT.md`), but left these four alone: they're used *inside* RLS policies on other tables, and revoking PUBLIC/anon execute risks breaking RLS evaluation for those policies in ways that need dedicated regression testing before touching, not a same-session drive-by fix. |
| Leaked password protection is disabled in Supabase Auth | P2 | Supabase can check new passwords against HaveIBeenPwned.org; currently off. This is a project-level Auth setting (Authentication → Policies in the Supabase dashboard), not something reachable via the SQL/migration tooling available this session — no MCP tool exposes the Auth config API. Directly relevant now that Round 4/5 added real password-change and password-reset flows; worth enabling manually. |
| In-app UI text sizes have real, pre-existing drift (10/10.5/11/11.5/12/12.5/13/13.5/14/15/16px — 11 near-duplicate steps within a 6px range) | P2 | Predates the 2026-07-25 visual reset; carried forward as-is (documented in `DESIGN.md`'s Typography section) since the reset's scope was color/typeface/motion, not the underlying size ramp. A genuine consolidation to a smaller, named step count is real follow-up work. |
| The 2026-07-25 dark/green visual reset does not yet include two of `DESIGN.md`'s more ambitious structural additions: Skymetrics-style sparklines inside stat tiles, and a collapsible icon-only sidebar state | P2 | Everything else from the audit's action list was completed the same session: the 3 zero-focus-indicator fields (Drafts title/body, Ideas title) and the remaining `outline-none` inputs across Team/Deals/Ideas all now have a real `focus-visible` outline; `prefers-reduced-motion` support shipped with the token rebuild; Deals' kanban and Drafts' split-pane were genuinely reworked for mobile (scroll-snap single-column carousel below `sm`; Drafts becomes a real list↔editor view with a back button below `md`, not just horizontal scroll) — verified live at 375px, not just claimed; the Hero.tsx stray hex is now a `var(--color-lavender)` reference, not a literal; Toast's `border-l-4` is gone. A sitewide orchestrated staggered-motion pass beyond marketing's `.reveal-up` remains open — real follow-up work, not attempted this round. |
